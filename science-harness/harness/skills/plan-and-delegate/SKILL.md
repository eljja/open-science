# 계획과 위임 (plan-and-delegate)

## 언제 계획하나
- 단계 ≥3, 산출물 ≥2, 또는 10분 이상 계산 → `.science/plan.md` 작성 후 사용자 승인.
- 질문/조회/한 번의 계산 → 바로 실행.

## plan.md 형식
```
# <작업 한 줄 요약>
타당성: 높음|중간|낮음 — <핵심 한계 1–2문장>
산출물: <파일 목록>
## 단계 1: <제목> — <1–3문장> [트랙: 단독|병렬 A/B]
...
```
각 단계 시작/완료 시 상태를 갱신(`[진행]`, `[완료]`, `[건너뜀: 이유]`).

## 위임 규칙
- **독립 트랙만** 병렬 위임(서로의 출력이 필요 없는 것). 의존 관계면 순차.
- 서브에이전트는 내 대화를 모른다 → task 에 **하드 요구사항**(전체 데이터 사용, 기준 문헌, 깊이, 출력 경로/스키마)을 모두 쓴다.
- 입력 파일은 경로를 명시해 넘기고, 출력은 정해진 경로/스키마로 받는다.
- 시간/자원 예산을 넘겨줄 때는 깊이를 줄여도 되는지 명시.
- 승인 대기(네트워크/권한)로 막힌 자식의 결과를 **대신 만들지 않는다**. 합성 데이터 대체 지시 금지.

## 서브에이전트 출력 계약
모든 서브에이전트는 마지막에 다음을 반환:
```
## 결과
<요약 + 산출물 경로>
## deviations
- none  |  - <task 대비 줄이거나 바꾼 것: 부분집합, 대체 소스, 건너뛴 항목>
```
부모는 결과를 보고하기 전에 deviations 를 읽고, 부분/샘플 입력에서 나온 “없음/감소”는 “이 깊이에서는 평가되지 않음”으로 보고한다.

## 종합
- 트랙별 결과를 표로 합치고, 수치는 각 산출물 파일에서 다시 읽어 인용.
- 마지막에 reviewer 서브에이전트(읽기 전용) 1회.
